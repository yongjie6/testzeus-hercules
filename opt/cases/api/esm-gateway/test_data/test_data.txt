# 被测对象：ESM V3.0 小程序服务端接口（esm-miniapp-gateway）

本套件测的是 HTTP 接口，不是页面。不要打开浏览器，也不要驱动小程序。

契约真源：
- 方法与路径：idl/esm/v1/esm_gateway.proto
- 资料、首页、报告结构：idl/esm/v1/esm_profile.proto
- 业务错误码：idl/error_code_esm.go
- 调用顺序说明：openspec/changes/add-esm-v21-backend/frontend_api_flow.md

## 工具路由

target_helper 固定用 api。本套件只用这四个工具：

- `esm_new_user`：建一个全新测试用户当前置条件。
- `esm_call`：调一个网关接口，返回断言要看的字段。
- `esm_wait_report`：等 Agent 把报告写回。
- `esm_wait_chat_reply`：等助手回复落库。

不要用 `generic_http_api`，也不要用 open_url、click、get_page_text 这些浏览器工具。
`generic_http_api` 不会带泳道头、不会补 baseReq、也不会带登录态，用它必然拿不到正确结果。

## 跨步骤取值：用 ${变量}，不要手抄

用例里的 id 一律不要从上一步的返回里"看着抄"到下一步——那些是
`scale_result_1787579309015_5fc762d981300012` 这种长随机串，抄错一位整条用例就废了，
而且失败现象和接口本身出错分不清。

产生值的那次调用顺手捕获，后面直接引用：

```
调用 POST /api/esm/v1/chat/create，...，用 extract_json 捕获 {"chatId": "$.body.chat.chatId"}
调用 POST /api/esm/v1/chat/message/send，...，body 传 {"chatId": "${chatId}", ...}
```

- `extract_json` 是 `esm_call` / `esm_wait_report` / `esm_wait_chat_reply` 的参数，
  写成 `{"变量名": "JSONPath"}`，路径打到哪匹配不上就直接报错，不会静默留空。
- `${变量}` 可以出现在 `path` / `body_json` / `query_json` 里，请求发出前替换。
- **变量名只能用字母数字下划线**，不能带点——框架的占位符正则是
  `[A-Za-z_][A-Za-z0-9_]*`，写成 `${A.userId}` 匹配不上，会原样发给服务端。

`esm_new_user` 建的用户会自动发布这几个变量，不用捕获：

| 变量 | 内容 |
|---|---|
| `${A_userId}` | 标签 A 的 userId |
| `${A_resultId}` | 标签 A 的量表 resultId（做完量表后才有值） |
| `${A_phone}` | 标签 A 的手机号 |
| `${A_gender}` | 标签 A 的性别枚举（没填资料的用户是空串） |
| `${A_birthDate}` | 标签 A 的出生日期（没填资料的用户是空串） |

标签 B、C 同理，把 A 换成对应标签。

**A、B、C 的性别和出生日期默认是不一样的**，这是故意的：对话和报告工作流现在会同时收到
双方的年龄和性别，两边用同一套属性的话，传错边或者漏传都测不出来。用例需要某个具体取值时
才给 `esm_new_user` 显式传 `gender` / `birth_date`。

## 判定口径

网关对业务失败也返回 HTTP 200，成败不体现在 HTTP 状态码上。

- 成功：`statusCode == "0"`
- 失败：`statusCode != "0"`，具体原因看 `bizCodeName`

断言只看 `statusCode` 和 `bizCodeName`，不要用 `httpStatus` 判断成败。

## JSON 约定

对外 JSON 走 protojson：

- 字段名是 lowerCamelCase，例如 `userInfoCompleted`、`entryStage`。
- int64 序列化成字符串，例如 `"54109"`、`"0"`。传参时也传字符串。
- 枚举传全名字符串，例如 `GENDER_MALE`、`AVATAR_SOURCE_WECHAT`。

`esm_call` 返回的 `body` 是响应里除 `baseResp` 外的全部内容，用例里写的
`body.xxx` 就按这个结构取。

## 常用枚举

- `HomeEntryStage`：HOME_ENTRY_STAGE_COMPLETE_USER_INFO / HOME_ENTRY_STAGE_ANSWERING / HOME_ENTRY_STAGE_HOME
- `Gender`：GENDER_UNSPECIFIED / GENDER_MALE / GENDER_FEMALE / GENDER_OTHER
- `AvatarSource`：AVATAR_SOURCE_WECHAT / AVATAR_SOURCE_UPLOAD
- `UserInfoAuditStatus`：USER_INFO_AUDIT_STATUS_NOT_REQUIRED / USER_INFO_AUDIT_STATUS_PASSED / USER_INFO_AUDIT_STATUS_REJECTED

## 环境说明

默认打测试环境泳道 `feat-esm-v3-0`，由 `ESM_BASE_URL` / `ESM_LANE` 控制，工具会自动带上
`lane`、`x-lane` 和 `X-Product-ID` 头。

产品标识固定是 `esm_miniprogram`（`ESM_PRODUCT_ID` 可覆盖），和真实小程序、四个 esm-* 服务
的默认值一致。这个值不只是打点：量表结果的手机号绑定按 `(product_id, phone_hash)` 建索引，
换一个产品标识就是换一套数据命名空间。

微信两段 code 换登录态是真实小程序链路，自动化拿不到有效 code；`esm_new_user` 走测试环境
的手机号注册拿同一套 token，网关只从 token 解析 uid，对网关侧契约等价。所以本套件里凡是
需要登录态的用例，都用 `esm_new_user` 建用户，只有专门测微信 code 校验的用例才直接调
微信登录接口并断言失败错误码。
